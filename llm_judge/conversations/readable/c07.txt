[13] SYSTEM  (FINAL_CHECK)
Checkpoint is exactly right, and that's the whole idea. In Express, every request to a route can be passed through one or more functions before it reaches the controller, each one gets handed `(req, res, next)`, and calling `next()` is what lets it continue on to the next checkpoint or the controller itself. It's the same shape as a Flask before_request hook, or a decorator wrapped around a view, something that runs on the way in and decides whether the request proceeds.

This file is that checkpoint for `/auth/forgot`. It keeps a map of IP to recent request timestamps, and:

```
if (recent.length >= 6) return res.status(429).json({ error: 'Too many requests' });
```

returns 429 and stops there, the controller never runs, which is the "no `next()` called" branch. Otherwise it records the timestamp and calls `next()` to let the request through.
